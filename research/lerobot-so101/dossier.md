## 10-line summary

1. The SO-101 is a 6-motor, ~$120–$230 open-hardware (Apache-2.0) desk arm; LeRobot (Apache-2.0, Python ≥3.12) is its only first-party control stack, running on a host PC over USB-serial at 1 Mbps to Feetech STS3215 bus servos. VERIFIED.
2. There is **no safety hardware**: no e-stop, no protective stop, no brakes; the only "stop" is torque-off via the serial bus or power removal, and position clipping (`max_relative_target`) is **off by default**. VERIFIED.
3. Control authority is decided entirely inside one Python process on the host: `lerobot-teleoperate`/`lerobot-record` are human-only, `lerobot-rollout` is policy-driven with five strategies, and only the **`dagger` strategy** mixes the two inside a run. VERIFIED.
4. The **only persisted control-authority label** is the per-frame boolean `intervention` written by the DAgger strategy; in its default mode (`record_autonomous=False`) **autonomous frames are not recorded at all**, and PAUSED frames are never recorded in either mode. VERIFIED (and confirmed on public Hub datasets).
5. Dataset `timestamp` is synthetic (`frame_index / fps`); no wall-clock, no operator identity, no clock source is stored anywhere in LeRobotDataset v3.0. VERIFIED.
6. The HIL-SERL path carries an in-memory `is_intervention` flag (gamepad RB / keyboard keys) to the learner and to a per-episode "Intervention rate" metric, but **never writes it to the dataset**. VERIFIED.
7. The strongest tamper-resistant physical signal is **leader-bus traffic**: the host polls the leader arm's `Present_Position` only while a human is driving, and writes `Torque_Enable`/`Goal_Position` to the leader only at DAgger hand-overs; a UART tap on the leader bus observes this without touching the control loop. VERIFIED (code) / UNKNOWN (tap latency not measured).
8. Native read-only taps: Foxglove WebSocket (`ws://127.0.0.1:8765`, topics `/observation/state`, `/action/state`, `/observation/images/<cam>`), Rerun gRPC, stdout log lines (`Phase transition: autonomous -> paused`), parquet files; async inference uses **plaintext gRPC on :8080** with no authentication. VERIFIED.
9. Simulation: MuJoCo/URDF models of the SO-101 ship in SO-ARM100; LeIsaac (Isaac Lab) exposes SO-101 tasks through LeRobot EnvHub; `gym_hil` (the HIL-SERL sim) is a Franka Panda, not an SO-101. The sim paths do not reproduce the serial-bus or DAgger-phase signals. VERIFIED.
10. Regulation: EU Machinery Reg. 2023/1230 (applies 20 Jan 2027) Annex III 1.2.1 requires one-year logging of safety-related decisions for self-evolving control and 1.2.5 governs mode selection; AI Act Art. 12/14/19/26(6) logging and human-oversight duties for Annex I machinery now apply from 2 Aug 2028 (Reg. 2026/1744). A hobby SO-101 is rarely in scope, but a commercial deployment would be. VERIFIED (Annex III 1.2.1 and 1.2.5 fragments from EUR-Lex snippets) / CLAIM (application dates and AI Act wording: concordant secondary sources, primary not re-opened).

## 3. Software architecture

**Layers (task → motor command), all in one host process:**

1. **Entry script** (`lerobot-teleoperate`, `lerobot-record`, `lerobot-rollout`, `lerobot-replay`, `python -m lerobot.rl.gym_manipulator`, `lerobot.rl.actor`) builds a `Robot` (`SOFollower`) and optionally a `Teleoperator` (`SOLeader`, keyboard, gamepad, phone) from dataclass configs (draccus CLI). VERIFIED [teleop_loop](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/scripts/lerobot_teleoperate.py#L155) (acc. 2026-10-30)
2. **Processor pipelines** (`teleop_action_processor`, `robot_action_processor`, `robot_observation_processor`; identity by default) transform dict actions/observations; end-effector teleops (gamepad/keyboard/phone) insert IK via `robot_kinematic_processor.py`. VERIFIED [record_loop](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/scripts/lerobot_record.py#L228) (acc. 2026-10-30)
3. **`SOFollower.send_action()`** strips the `.pos` suffix, optionally clips by `max_relative_target` (requires an extra `Present_Position` read), then `bus.sync_write("Goal_Position", …)`. It returns the action actually sent. VERIFIED [send_action](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/robots/so_follower/so_follower.py#L205) (acc. 2026-10-30)
4. **`FeetechMotorsBus`** (scservo_sdk + pyserial) serialises `Goal_Position` sync-writes and `Present_Position` sync-reads over the half-duplex TTL bus. VERIFIED [feetech.py](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/motors/feetech/feetech.py#L113) (acc. 2026-10-30)
5. **Servo firmware** closes the position loop with PID gains written at connect (`P=16, I=0, D=32`), `Operating_Mode=POSITION`, acceleration 254. VERIFIED [config](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/robots/so_follower/config_so_follower.py#L45) (acc. 2026-10-30), [configure()](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/robots/so_follower/so_follower.py#L159) (acc. 2026-10-30)

**Control loop and rates.** Single-threaded loop: `obs = robot.get_observation()` → action source → `robot.send_action()` → `precise_sleep` to hold `fps`. Default `fps=60` for `lerobot-teleoperate`, `fps=30.0` for `lerobot-rollout`; `lerobot-record` uses `dataset.fps`. If the loop overruns, a warning is logged and frames are dropped (no hard real-time). VERIFIED [teleop fps](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/scripts/lerobot_teleoperate.py#L140) (acc. 2026-10-30), [rollout fps](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rollout/configs.py#L240) (acc. 2026-10-30), [overrun warning](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/scripts/lerobot_record.py#L353) (acc. 2026-10-30)

**Where human commands enter.** `teleop.get_action()` → for `SOLeader` this is a `sync_read("Present_Position")` of the leader bus; for keyboard/gamepad/phone it is a device poll. VERIFIED [SOLeader.get_action](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/teleoperators/so_leader/so_leader.py#L146) (acc. 2026-10-30)

**Where AI actions enter.** `lerobot-rollout`: `send_next_action()` in `rollout/strategies/core.py` pulls from an inference engine (`sync` = one policy call per tick; `rtc` = real-time chunking) and calls `robot.send_action`. Async inference: `RobotClient` streams observations to a `PolicyServer` over gRPC and plays back action chunks. VERIFIED [lerobot_rollout.py](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/scripts/lerobot_rollout.py#L27) (acc. 2026-10-30), [services.proto](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/transport/services.proto#L38) (acc. 2026-10-30)

**Processes and middleware.** No ROS, no DDS. One Python process per arm pair; optional extra processes: Foxglove WebSocket server (in-process thread), Rerun viewer (separate process, gRPC), async-inference `PolicyServer` (separate host, gRPC :8080), HIL-SERL learner (gRPC). Keyboard/pedal listeners run as daemon threads inside the control process. VERIFIED [init_foxglove](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/utils/foxglove_visualization.py#L75) (acc. 2026-10-30), [rerun connect](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/utils/rerun_visualization.py#L62) (acc. 2026-10-30), [policy server port](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/async_inference/configs.py#L55) (acc. 2026-10-30), [pedal thread](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rollout/strategies/dagger.py#L199) (acc. 2026-10-30)

**Mode arbitration.** There is no arbiter module. Which source is called is decided by (a) which script is running and (b) in DAgger, a three-state machine `AUTONOMOUS / PAUSED / CORRECTING` mutated from keyboard/pedal threads and consumed once per tick. VERIFIED [DAggerPhase](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rollout/strategies/dagger.py#L83) (acc. 2026-10-30), [transitions](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rollout/strategies/dagger.py#L92) (acc. 2026-10-30)

## 7. Passive observation

**Ranking of taps (safest first):**

1. **Hardware UART tap on the leader and follower TTL buses.** The STS3215 bus is a single half-duplex TTL data line at 1 Mbps (8N1) shared by the adapter and all six servos; a logic-level UART receiver wired to the data line and GND sees every instruction packet (host → servo: `Goal_Position` sync-writes, `Torque_Enable` writes, `Present_Position` sync-read requests) and every status packet (servo → host). Nothing is transmitted by the tap, so the control loop cannot be affected and a tap crash is invisible to LeRobot. Gives S3–S7 at bus rate. Cost: 0 CPU on the host. **Latency: UNKNOWN (not measured in this run)**; packet-level, so bounded by one packet time (~0.1–0.3 ms at 1 Mbps for the packet sizes involved — INFERRED, not measured). Tag: VERIFIED (bus facts [baudrate](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/motors/feetech/feetech.py#L44) (acc. 2026-10-30), [register map](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/motors/feetech/tables.py#L41) (acc. 2026-10-30)) / UNKNOWN (tap hardware not tested).
2. **Foxglove WebSocket client** on `ws://127.0.0.1:8765` (requires the operator to launch with `--display_data=true --display_mode=foxglove`). Subscribe-only; a client disconnect is harmless. The server itself runs inside the control process, so JPEG compression / channel logging **adds CPU to the control loop whether or not an observer is connected**; CPU figures UNKNOWN (not measured). ## 11. Threat model — making human work look autonomous on this platform

| # | Technique | What would expose it |
|---|---|---|
| T1 | Run `lerobot-record` (human teleop) and name the dataset `rollout_<x>` or describe it as a policy run; `lerobot-record` only rejects `eval_`. | Absence of `intervention` column while claiming DAgger; **leader-bus polling (S3)** throughout; no inference process/GPU load; no gRPC traffic. |
| T2 | Use DAgger corrections-only mode (default) and report only the saved episodes as "the run": all human frames are visible, but autonomous time is unrecorded, so the human fraction cannot be computed; conversely, delete human episodes with `delete_episodes` from a `record_autonomous=true` dataset. | Gaps between episodes; `episode_index` renumbering; Hub commit history; S3 tap; wall-clock from a tap vs. `frame_index/fps` duration. |
| T3 | Rewrite the `intervention` column with `add_features`/`remove_feature` (official tools). | Hash of the original parquet; Hub commit history; cross-check against leader-bus log. |
| T4 | `lerobot-replay` a teleop episode on the follower and film it as "autonomous". | Follower-bus commands identical to a stored `action` column; no observation→policy dependency (perturb the scene: replay does not react); no inference process. |
| T5 | Drive with a second, hidden teleop process (phone over Wi-Fi, gamepad, or a decoy script polling the leader) while `lerobot-rollout --strategy.type=base` appears to run. | Only one process can own `/dev/ttyACM*` without packet corruption → the decoy would have to be the real controller; the leader bus (S3) or Wi-Fi (phone) shows traffic; `phone.enabled`. |
| T6 | Press "pause" instead of "correction" and physically push the follower while torque is on/off (kinesthetic help) — never flagged. | `Present_Load`/`Present_Current` spikes, position change with constant `Goal_Position` (S6 constant + S17), video. |
| T7 | Use the episodic strategy: human teleop during reset phases is never recorded; long "resets" can hide corrective work. | S3 polling during gaps between episodes; wall-clock gaps vs. recorded duration. |
| T8 | Re-record episodes (`←`, `rerecord_episode`) until success; survivorship bias presented as success rate. | `clear_episode_buffer` leaves no trace in the dataset; only an external log/tap of attempts exposes it. |
| T9 | Disable visualization (`display_data=false`) and logging so no S2/S8 evidence exists. | Taps that do not depend on operator flags: S3–S7 bus taps, pcap. |
| T10 | Edit `timestamp`/`fps` to stretch or compress apparent durations. | `timestamp` must equal `frame_index/fps` (writer invariant); video frame count vs. parquet rows. |

Data that cannot be faked without physical access or a second controller: leader-bus traffic and follower `Torque_Enable` state captured by an independent tap with its own clock and hash chain.

### 14.7 Body parts that can be human-driven while others run on AI (item F)

* Single SO-101: **one scope** (`whole_robot`). All six joints (gripper included) are commanded in one `Goal_Position` sync-write; no per-joint authority switch. VERIFIED [send_action](https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/robots/so_follower/so_follower.py#L205) (acc. 2026-10-30)
* Bimanual `bi_so_follower` / `bi_so_leader`: two arms but **one** DAgger state machine and **one** `intervention` boolean, so LeRobot cannot run one arm on policy and the other on human; declare `left_arm` / `right_arm` and emit identical transitions (scope-weighted share = any-human share). ### 14.8 Cases the rules do not cover (collected flags)

1. **Replay** (`lerobot-replay`, or a policy that replays a dataset): no state. Proposed: `ai` with `actor_id` prefix `replay:` and separate reporting of replay time.
2. **Held with no controller** inside a task (DAgger PAUSED; HIL-SERL record mode between interventions; torch warm-up): mapped to `shared` / `shared` / `ai` here, but the taxonomy has no "hold" state; document these mappings normatively or add `hold`.
3. **Multi-step hand-over** `ai → shared → human_local` over several seconds must count as one intervention; `simultaneity_window_s` (0.5 s) is too short. Proposed: an intervention opens at the first transition out of `ai` and closes at the next return to `ai`.
4. **Local vs remote** is not derivable from any LeRobot signal; declare it at `session_start`.
5. **Firmware safety cut-outs** are per joint and silent to software; a per-joint `safety_stop` inside a single-scope robot is not expressible unless joints are declared as scopes.
6. **Unrecorded human time by design** (PAUSED, resets, corrections-only mode): a dataset-only report always has unbounded `unknown_share` and is therefore `incomplete`; only an external observer (bus tap + log tail) can bound it.
7. **No `help_request` / `approval` / `hint` pathway** exists; `ai_requested_help` can never be legitimately emitted from LeRobot signals.
