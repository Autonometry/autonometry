# Integration notes — observing an SO-101 / LeRobot stack passively, starting in simulation

Pinned: lerobot **v0.6.1** (commit `7e241bd630a3719a56157a497ce5d08f244784f1`), SO-ARM100 commit `a758567c3978dfeefe282ede0500085a48fe8f78`, Python ≥3.12. Access date 2026-10-30. The observer never opens the robot's serial port and never imports into the control process.

## A. Minimum steps in simulation (no hardware)

1. Create an isolated environment: `python -m venv .venv && . .venv/bin/activate && pip install "lerobot[feetech]==0.6.1" "foxglove-sdk>=0.25.1,<0.26" pyarrow`. (`[feetech]` pulls `feetech-servo-sdk>=1.0,<2` + pyserial; not needed for sim but keeps the import graph identical to the real run.)
2. Clone the pinned tree for the mocks: `git clone https://github.com/huggingface/lerobot && cd lerobot && git checkout 7e241bd630a3719a56157a497ce5d08f244784f1`; the registered `type=mock_teleop` lives in `tests/mocks/mock_teleop.py` (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/teleoperators/utils.py#L32). **UNKNOWN:** whether a mock `so_follower` robot type can be registered for `lerobot-rollout` without a serial port — if not, step 3 falls back to the gym path in step 4.
3. Exercise the real DAgger state machine with mocks: `lerobot-rollout --strategy.type=dagger --robot.type=<mock robot> --teleop.type=mock_teleop --policy.path=<any small ACT checkpoint> --dataset.repo_id=local/rollout_sim_test --dataset.push_to_hub=false --dataset.root=./ds --strategy.record_autonomous=true --display_data=true --display_mode=foxglove --fps=30 --duration=120`. Press `space` (pause), `tab` (correction), `tab`, `space`, `esc` (defaults in `DAggerKeyboardConfig`, https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rollout/configs.py#L106). Set `--dataset.push_to_hub=false` explicitly: the default is `True` (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/configs/dataset.py#L43).
4. Alternative sim that exercises the HIL-SERL intervention path: `pip install "gym-hil>=0.1.14,<0.2"` and run `python -m lerobot.rl.gym_manipulator --config_path <env_config.json>` with `task: PandaPickCubeKeyboard-v0`, `fps: 10`, `mode: record` (https://huggingface.co/docs/lerobot/hilserl_sim). This is a Franka, not an SO-101; it reproduces S9/S10 but **does not** write `is_intervention` to the dataset (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rl/gym_manipulator.py#L648).
5. Observer tap 1 — Foxglove: connect a `foxglove` WebSocket client (or the Foxglove app) to `ws://127.0.0.1:8765`; subscribe to `/action/state`, `/observation/state`, `/observation/images/<cam>` (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/utils/foxglove_visualization.py#L135). Record `log_time` (server `time.time_ns()`, https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/utils/foxglove_visualization.py#L215) and the JSON `scalars` list. The server lives inside the control process; the observer must only subscribe.
6. Observer tap 2 — log tail: start step 3 with stdout redirected (`... 2>&1 | tee rollout.log`) or pass a `log_file` if the script exposes it; parse lines matching `Phase transition: (\w+) -> (\w+)` (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rollout/strategies/dagger.py#L659); the prefix carries `YYYY-MM-DD HH:MM:SS` local time (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/utils/utils.py#L70).
7. Observer tap 3 — dataset watcher: `inotify`/polling on `./ds/local/rollout_sim_test/data/chunk-*/file-*.parquet`; after each `save_episode()` read columns `episode_index, frame_index, timestamp, intervention` with pyarrow (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/rollout/context.py#L422). Remember `timestamp == frame_index / fps` is synthetic (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/datasets/dataset_writer.py#L225); use the file mtime and S2 log times for wall-clock anchoring.
8. Build the tamper-evident record: for every S2 transition, S8 message batch and S1 episode, append `{wall_time_ns, source, payload_sha256, prev_hash}` to the observer's own hash-chained log; also hash each parquet/mp4 file at close time so later `add_features`/`delete_episodes` edits are detectable.
9. Reconcile in sim: the fraction of frames with `intervention==true` from step 7 must equal the CORRECTING time share derived from step 6 (±1 s because log timestamps are 1 s); PAUSED time appears **only** in step 6 — treat it as `idle`, not `ai`.
10. Verify observer isolation: kill the observer mid-run; the rollout must continue (it has no dependency on subscribers). Then kill the rollout; the observer must close its chain with a `source_lost` record.

## B. Steps that only apply on real hardware (for later; versions as above)

11. Add the leader-bus UART tap (S3–S5): a non-transmitting 3.3 V-tolerant UART RX on the leader bus data line at 1 000 000 baud 8N1 (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/motors/feetech/feetech.py#L44); decode Feetech protocol-0 packets; classify `READ Present_Position(56)` polls (human driving), `WRITE Torque_Enable(40)` and `WRITE Goal_Position(42)` on the leader (hand-overs). Register map: https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/motors/feetech/tables.py#L41. **Never** open `/dev/ttyACM*` from the observer (no exclusive lock is set, https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/robots/so_follower/so_follower.py / motors_bus.py; concurrent reads corrupt the controller's packets).
12. Add the follower-bus tap (S6, S7) the same way; `Goal_Position` constant for >1 s while torque is on = PAUSED hold; no `Goal_Position` traffic = idle/torque-off.
13. If async inference is used, capture TCP :8080 (`grpc.insecure_channel`, https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/async_inference/robot_client.py#L110) to attribute `ai` segments to a remote policy server and to time one-way latency.
14. Classify `lerobot-replay` separately: follower-bus commands that match a known dataset `action` column bit-for-bit are `replay`, not `ai` (https://github.com/huggingface/lerobot/blob/7e241bd630a3719a56157a497ce5d08f244784f1/src/lerobot/scripts/lerobot_replay.py#L130).
15. Report autonomy as time-share per class {ai, human_local, human_remote, idle, replay, safety_stop} with Wilson/bootstrap CIs over episodes, and always report the **unobserved** share (PAUSED, resets, unrecorded autonomous time) explicitly.

## C. Known gaps to budget for

- No e-stop or protective stop exists on the platform; `safety_stop` can only mean torque-off or power-off.
- `robot_type` is `so_follower` for both SO-100 and SO-101; record the arm identity out-of-band.
- Operator identity, time zone and NTP state are not available from LeRobot; capture them in the observer's own metadata.

## D. Event emission recipe (taxonomy v0.1, `event.schema.json`)

16. `session_start`: `scopes=["whole_robot"]` (or `["left_arm","right_arm"]` for `bi_so_follower`, transitions always emitted for both), `initial_states` = `idle` until the first S2/S3/S6 evidence, `heartbeat_interval_s=1`, `hint_policy="hint_as_shared"` (irrelevant here: no hint path), `task_registry_hash` = sha256 of the frozen `single_task` list, `plan_hash` = sha256 of the planned reset/calibration blocks; `note` = `{"lerobot":"v0.6.1","commit":"7e241bd630a3719a56157a497ce5d08f244784f1","host_utc_offset":...,"local_or_remote_teleop":"declared by observer"}`.
17. From S2 log lines (preferred when available): `-> autonomous` → `transition state=ai actor_id=ai:<policy.path> reason=null`; `-> paused` → `transition state=shared reason=human_initiated actor_id=<op>`; `-> correcting` → `transition state=human_local reason=human_initiated actor_id=<op>`. Count one intervention per `ai → shared → human_local` sequence (flag 3). `ts` = observer UTC clock at the moment the line is read; put the log's own `YYYY-MM-DD HH:MM:SS` in `note`.
18. From S1 (dataset watcher, post hoc): per episode, `task_start(task_definition_id=single_task)` at `frame_index=0`, a `transition` whenever `intervention` changes between consecutive frames (`true→human_local`, `false→ai`), `task_end(outcome=unknown)` at the last frame. `ts` must be reconstructed from an external anchor (file mtime of the parquet or the S2 line for `Episode saved`) plus `frame_index/fps`; mark these events `note="ts_reconstructed"`. Time between episodes is `unknown` (never recorded) unless S2/S3 evidence exists.
19. From S3/S4/S6 (bus taps, hardware only): leader polling starts → `transition human_local`; leader `Torque_Enable=1` → `transition shared`; leader `Torque_Enable=0` followed by polling → `human_local`, followed by no polling and follower commands resuming → `ai`; follower `Goal_Position` absent for ≥ 30 s with no open task → `transition idle`; follower `Torque_Enable=0` after a non-zero `Status` byte → `transition safety_stop reason=safety`; bus silent → `transition unknown`.
20. Keys/buttons: `→` → `task_end(outcome=unknown)`; `←` → `task_end(outcome=aborted)`; gamepad Y/X/A → `task_end(success|failure|aborted)`; `Esc` → `session_end`.
21. Never emit `help_request`, `approval` or `hint` for this platform (no such pathway exists); never emit `reason=ai_requested_help`.
22. `lerobot-replay` sessions: emit `transition state=ai actor_id=replay:<repo_id>/<episode>` and report replay time separately (taxonomy gap, flag 1).
23. Report fields that will always be degraded on this platform: `unknown_time / observed_time` is unbounded for dataset-only input (mark `incomplete`); `safety_stops_per_active_hour` = 0 by construction (no safety function); `supervision` level must be declared by the observer (LeRobot has no notion of it).
