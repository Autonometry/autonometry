### Telling teleop from Nav2 in the recording

- **Topic-level rule (works in a plain bag):** a `/cmd_vel` message whose `twist` equals (within float tolerance) the latest `/cmd_vel_smoothed` message and whose `recv_timestamp` is within a few ms of it is Nav2 output (collision_monitor relays `cmd_vel_smoothed` -> `cmd_vel`) [VERIFIED: https://github.com/turtlebot/turtlebot4/blob/7fd29fb420e906f3aca4a904adb54b69b11c7c00/turtlebot4_navigation/config/nav2.yaml#L299, acc. 2026-10-31] [VERIFIED: https://github.com/turtlebot/turtlebot4/blob/7fd29fb420e906f3aca4a904adb54b69b11c7c00/turtlebot4_navigation/config/nav2.yaml#L300, acc. 2026-10-31]; a `/cmd_vel` message with no matching `/cmd_vel_smoothed` is from a human or script. `/cmd_vel_nav` carries only Nav2 controller/behavior output [VERIFIED: https://github.com/ros-navigation/navigation2/blob/d5d768b7b38a05e7cfd2b6c693b786b402161bed/nav2_bringup/launch/navigation_launch.py#L137, acc. 2026-10-31] [VERIFIED: https://github.com/ros-navigation/navigation2/blob/d5d768b7b38a05e7cfd2b6c693b786b402161bed/nav2_bringup/launch/navigation_launch.py#L181, acc. 2026-10-31].
- **Header rule (weak, forgeable):** `header.frame_id == "teleop_twist_joy"` marks the controller [VERIFIED: https://github.com/ros2/teleop_twist_joy/blob/556a07100ee745f68619de84a95d3c84a4892ab9/src/teleop_twist_joy.cpp#L94, acc. 2026-10-31]; keyboard teleop leaves it empty unless `frame_id` is set [VERIFIED: https://github.com/ros2/teleop_twist_keyboard/blob/ed06da483e4acef8d0ab225557d64e6597c9bdf2/teleop_twist_keyboard.py#L144, acc. 2026-10-31]; Nav2 frame_id is the Nav2 track's to document.
- **Joystick rule:** human joystick control exists only while `/joy.buttons[4]` or `[5]` is 1 (dead-man) [VERIFIED: https://github.com/ros2/teleop_twist_joy/blob/556a07100ee745f68619de84a95d3c84a4892ab9/src/teleop_twist_joy.cpp#L330-L333, acc. 2026-10-31] [VERIFIED: https://github.com/turtlebot/turtlebot4_robot/blob/28e115f86930bb3273f1a1aa4738dbd8747513f0/turtlebot4_bringup/config/turtlebot4_controller.config.yaml#L76, acc. 2026-10-31]; exactly one all-zero `/cmd_vel` follows release [VERIFIED: https://github.com/ros2/teleop_twist_joy/blob/556a07100ee745f68619de84a95d3c84a4892ab9/src/teleop_twist_joy.cpp#L341-L344, acc. 2026-10-31].
- **Publisher identity (definitive):** only available live — `ros2 topic info -v /cmd_vel` or the observer's `publisher_gid` log; rosbag2 stores `topic_name`, `recv_timestamp`, `send_timestamp` only [VERIFIED: https://github.com/ros2/rosbag2/blob/cb8fa198b93bfed90e2417b52b8645fb9ef89c2b/rosbag2_storage/include/rosbag2_storage/serialized_bag_message.hpp#L27, acc. 2026-10-31] [VERIFIED: https://github.com/ros2/rosbag2/blob/cb8fa198b93bfed90e2417b52b8645fb9ef89c2b/rosbag2_storage/include/rosbag2_storage/serialized_bag_message.hpp#L39, acc. 2026-10-31]. In simulation the GUI teleop appears as publisher `cmd_vel_bridge`, Nav2 as `collision_monitor`, keyboard as `teleop_twist_keyboard`.
- **Time base:** with `--use-sim-time` the bag `recv_timestamp` is `/clock`; the Autonomy Meter `ts` must still be the observer's UTC wall clock with `x_src_clock: sim` (definitions.md Section 8) [VERIFIED: https://github.com/ros2/rosbag2/blob/cb8fa198b93bfed90e2417b52b8645fb9ef89c2b/rosbag2_transport/src/rosbag2_transport/recorder.cpp#L786, acc. 2026-10-31].


## B. Event-logging recipe (definitions.md v0.2, event.schema.json v0.2)

### B.1 Session preamble

1. Declare `scopes: ["base"]` and `initial_states: {"base": "idle"}` (the robot spawns docked; the only motion scope is the base — dossier 14E).
2. Freeze and hash the three registries before the session: task registry (e.g. `nav_to_pose_<name>`, `mapping`, `patrol`), plan (declared resets: `initial_pose`, `place_on_dock`), and the **device registry**. TurtleBot 4 device-registry template (dossier UC-11): `create3_button_1`, `create3_button_2`, `create3_button_power`, `hmi_button_1..4`, `manual_handling` → `local`; `tb4_controller` (Bluetooth pad; appears as node `teleop_twist_joy_node`, `frame_id teleop_twist_joy`) → `local`; `teleop_twist_keyboard` on the PC, `rviz2` (`rviz_pc_1`), Gazebo GUI teleop (`cmd_vel_bridge`) → `remote`. Anything else publishing `/cmd_vel` is an undeclared device → `human_remote` (definitions 6.10).
3. Write `session_start` with `heartbeat_interval_s: 1.0`, `hint_policy: hint_as_shared`, the three hashes, and the extension fields the dossier requires for this platform: `x_publishers` (GID → node/namespace/host for every publisher of `/cmd_vel`, `/cmd_vel_nav`, `/cmd_vel_smoothed`, captured from `ros2 topic info -v` or the observer's own `MessageInfo.publisher_gid`), `x_safety_config` (`safety_override`, `reflexes_enabled`, `reflexes.*`, `publish_hazard_msgs`, `raw_kinematics_min_pub_period_ms`, collision-monitor `enabled`), `x_config_changes` (e.g. `republisher.yaml` hazards uncommented — UC-10), `x_ros_domain_id`, `x_rmw`, `x_discovery_server`, `x_src_clock` (`sim` in Gazebo, `wall` on hardware).
4. Emit a `supervision` event (`remote_monitoring`, `n_supervisors`) — a human watching RViz is not a control state (definitions 6.4).

### B.2 Observable → event mapping (scope `base`)

| same | new `goal_id` while EXECUTING, sender is a declared human device | `transition shared / human_initiated` until the new path is followed or `hint_ttl_s`; `hint` under `hint_as_event` | UC-8(b) |
| same | `SUCCEEDED` / `ABORTED` | `task_end` `success` / `failure` (+ `x_nav2_error_code`) | Nav2 14D |

| `/hazard_detection` BACKUP_LIMIT + `cmd_vel.linear.x < 0` + `wheel_vels ≈ 0` | — | `safety_stop / safety` | base 14D |
| `/hazard_detection` BUMP/CLIFF/WHEEL_DROP/STALL + `wheel_vels ≠ 0` while command is 0/opposite, ≥ `min_reflex_duration_s` | — | `transition ai`, `actor_id ai:create3_reflex`, then back; `x_reflex_count` | UC-4 |
| `/kidnap_status.is_kidnapped` ≥ 1 s | — | `transition human_local / human_initiated` (`planned` + `plan_item_id` between tasks) | UC-20 |
| `/initialpose` from RViz before `task_start` | — | `transition human_remote / planned` (`plan_item_id initial_pose`) ended by the next event | UC-8(e) |
| `/initialpose`, `/speed_limit` from a human during a task | — | hint (`shared` under `hint_as_shared`) | UC-8(d) |
| `/dock_status.is_docked` true, no task, no command for `idle_threshold_s` | — | `transition idle` | base 14D |
| `/function_calls` = `Power`; `/battery_state` ≤ 12 % undocked for 60 s; all base topics vanish | — | `session_end` with `x_cause` | UC-12 |
| `/parameter_events` touching `safety_override`, `reflexes*`, `publish_hazard_msgs` | — | heartbeat with new `x_safety_config` | UC-19 |
| `/hmi/display`, `/hmi/led/*`, `/cmd_lightring`, `/cmd_audio` | — | heartbeat `x_ui_event` only | UC-15 |
| any `seq` gap, >`gap_tolerance_s` without heartbeat, volatile state topic before first message | — | `unknown` (loader), `x_signals_unknown` | definitions 2, UC-16 |

### B.3 Timestamps

`ts` is always the observer's UTC clock (NTP-disciplined). Keep the source stamp in `x_src_ts` with `x_src_clock`: `sim` under `use_sim_time` (all TB4 Gazebo launches), `wall` on hardware. Do not use `BehaviorTreeStatusChange.timestamp` as `x_src_ts` in simulation (it is BehaviorTree.CPP's own clock) and do not expect `TransitionEvent.timestamp` to be set (rcl_lifecycle never assigns it) — dossier 14B. Log `received_timestamp − source_timestamp` per publisher as a skew diagnostic (the Pi's chrony falls back to `local stratum 10` without internet).

### B.4 Observer sketch (rclpy, untested)

```python
# autonomy_meter_tb4_observer.py — read-only; subscribes best-effort/volatile; never publishes to the robot.
import rclpy, json, hashlib, datetime
from rclpy.node import Node
from rclpy.qos import QoSProfile, ReliabilityPolicy, DurabilityPolicy, HistoryPolicy
from geometry_msgs.msg import TwistStamped
from std_msgs.msg import String
from action_msgs.msg import GoalStatusArray

BE = QoSProfile(history=HistoryPolicy.KEEP_LAST, depth=10,
                reliability=ReliabilityPolicy.BEST_EFFORT, durability=DurabilityPolicy.VOLATILE)
TL = QoSProfile(history=HistoryPolicy.KEEP_LAST, depth=1,
                reliability=ReliabilityPolicy.RELIABLE, durability=DurabilityPolicy.TRANSIENT_LOCAL)

class Observer(Node):
    def __init__(self):
        super().__init__('autonomy_meter_observer')
        self.out = open('events.jsonl', 'a'); self.seq = 0; self.prev = GENESIS_HASH
        self.create_subscription(TwistStamped, 'cmd_vel', self.on_cmd_vel, BE)          # per-message publisher_gid
        self.create_subscription(TwistStamped, 'cmd_vel_smoothed', self.on_smoothed, BE)
        self.create_subscription(String, 'function_calls', self.on_function, BE)
        self.create_subscription(GoalStatusArray, 'navigate_to_pose/_action/status', self.on_nav_status, TL)
        # ... wheel_status, dock_status, joy, collision_monitor_state, behavior_tree_log, hazard_detection (if relayed)
    def on_cmd_vel(self, msg, info=None):
        # rclpy delivers rmw message info via the subscription's raw callback when requested;
        # publisher_gid attributes the message to a node from the session_start x_publishers map (UC-2).
        ...
    def emit(self, ev):
        ev.update(robot_id=ROBOT, session_id=SESSION, seq=self.seq,
                  ts=datetime.datetime.now(datetime.timezone.utc).isoformat(timespec='milliseconds').replace('+00:00','Z'),
                  prev_hash=self.prev)
        body = json.dumps(ev, sort_keys=True, separators=(',', ':'), ensure_ascii=False).encode()  # RFC 8785 for these value types
        ev['hash'] = hashlib.sha256(body).hexdigest(); self.prev = ev['hash']; self.seq += 1
        self.out.write(json.dumps(ev) + '\n'); self.out.flush()
```

Notes: (i) use `rclpy`'s message-info callback (`raw`/`MessageInfo`) to read `publisher_gid`; if your rclpy build does not expose it, fall back to the topic-level rule in UC-2 and flag `attribution_topic_level`. (ii) Subscribe to `navigate_to_pose/_action/status` with the transient-local profile so the current goal state arrives immediately. (iii) Run the observer on the PC for simulation; on hardware run it on the Pi if you need `/_do_not_use/*` (UC-10), otherwise on a PC that is a super client of the Pi's Discovery Server.

### B.5 Worked example

`tb4_example_events.jsonl` (companion file) is a 17-event session produced by the rules above — undock via Create 3 button (`shared`), RViz pose estimate (`human_remote`, `planned`), a Nav2 goal (`task_start`, `ai`), a recovery heartbeat, a keyboard-contention episode (`shared`, `cmd_vel_contention`), a collision-monitor STOP followed by a human takeover within 60 s (one intervention, reason `safety`, `related_seq`), an EStop button press (`safety_stop`, `x_trigger_kind human_button`), a cancelled task (`task_end aborted`), idle and `session_end`. Every event validates against `event.schema.json` v0.2 (jsonschema Draft 2020-12 with format checking; 0 errors) and the `hash`/`prev_hash` chain starts from `SHA-256("autonomy-meter/v0.2|tb4-standard-01|sim-2026-11-03-001")`. Expected report lines for it: human time = undock span + pose-estimate span + contention span + takeover span; `safety_stops` = 2 (one followed by a takeover → 1 intervention with reason `safety`); interventions = 3 (contention, takeover, cancel-hint); task t1 not autonomous, outcome aborted.

### B.6 Hardware deltas (when moving off the simulator)

1. `/cmd_vel` on the robot namespace is `TwistStamped` (Jazzy remap); legacy `Twist` publishers appear on `/cmd_vel_unstamped` — subscribe to both.
2. Hazards/kidnap/stop/wheel_vels are **not** relayed by default: uncomment them in `turtlebot4_bringup/config/republisher.yaml` and record the change in `x_config_changes`, or observe `/_do_not_use/*` on the Pi (UC-10).
3. Bluetooth controller: `/joy` and `/cmd_vel` come from the Pi; without `/joy` in the recording the dead-man is invisible.
4. Clock: the Pi may be free-running without internet; the observer's `ts` must come from its own NTP-synced clock.
5. Out-of-band paths with no ROS trace (BLE mode, webserver): detect by motion without a command (`/odom`, `/wheel_vels`) and log `unknown`.
