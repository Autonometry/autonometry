# Gaming: how autonomy share can be inflated, and what exposes it

Retrieval date: 2026-10-30. Source ids refer to `trust_sources.csv`; trust levels L1-L4 and the L-A/L-B/L-C machinery are defined in `trust.md`. Metric names follow Part 3 of the brief: time autonomy share (TAS), task autonomy rate (TAR), interventions per active hour (IPAH), time/distance between interventions (TBI), human minutes per task (HMPT). Rows are this review's analysis; the only external facts invoked are the logging-primitive properties cited in `trust.md`.

## 1. Principle

Every inflation tactic changes either the numerator (human time or interventions, made smaller), the denominator (active time or task count, made larger), or the record itself. A check exposes a tactic when it (a) is computed from data the reporter cannot shrink without also shrinking a quantity that is reported and bounded, or (b) compares two witnesses that would have to be corrupted consistently. Pre-registration (task definitions, exclusion rules, active-time rules fixed before the measurement window) converts "definition drift" from a judgement call into a detectable deviation.

## 2. Tactics and exposing checks

| # | Tactic | Effect on metric | Exposing metric, invariant or check | Trust level at which the check binds |
|---|---|---|---|---|
| 1 | Redefine tasks to be shorter or easier (split one task into many; drop hard sub-steps) | TAR up (more tasks with zero help); HMPT down; IPAH unchanged | Task-duration distribution drift test between reporting periods (two-sample test on log duration per task type; flag if median shifts > 25 % without a declared definition change); pre-registered task definitions with versioned ids; mandatory `task_definition_id` on every task; per-task-type reporting so a mix shift cannot hide behind a pooled rate | L1 (pre-registration), checked by any auditor |
| 2 | Pad idle time into the denominator (robot powered on, doing nothing, logged as `ai` or `idle` inside active time) | TAS up; IPAH down; TBI up | Active-time definition excludes `idle`; idle-share cap: `idle / wall_time` reported and a declared maximum (default 20 %) beyond which TAS must also be reported on productive time only; motion or task-progress evidence required for `ai` intervals (distance, joint motion, task events); human-minutes-per-task floor: HMPT cannot fall below the setup/teardown minimum observed in teleop reference sessions without explanation | L1 reporting; L2 fixes the idle intervals |
| 3 | Stop instead of taking over (robot enters `safety_stop` whenever a human would otherwise intervene; the stop is logged as non-human) | IPAH down; TAS up (stop time is not human time) | `safety_stop` rate per active hour and dwell distribution reported alongside IPAH; invariant: safety_stop episodes that end with a human action or a task abort are counted as interventions; cap on `safety_stop / active_time` (default 5 %) above which the period is reported as "stop-dominated"; task completion rate must be reported with TAR so that abandoned tasks do not vanish | L1 |

## 3. Invariants to compute on every report

These are cheap and should be run by the reference implementation before any interval is printed.

1. Partition: `ai + human_local + human_remote + shared + safety_stop + idle + unknown = wall_time` for each session, within one event resolution.
2. Chain: for every consecutive event pair, stored `h_{i-1}` equals the recomputed hash; for every consecutive checkpoint pair, a valid consistency proof exists (L2).
3. Time: event times non-decreasing within a chain; `|t_TSA - t_checkpoint| <= tau` for every timestamped checkpoint (L2).
4. Census: session ids form a contiguous counter per robot; missing ids are listed as excluded with reason (L2).
5. Tasks: `tasks_started = tasks_completed + tasks_aborted + tasks_in_progress`; every task has a `task_definition_id` present in the pre-registered list.
6. Floors and caps: HMPT >= declared reset minimum; `idle / wall_time` <= idle cap or dual reporting; `safety_stop / active_time` <= stop cap or "stop-dominated" flag; hints + approvals per task reported.
7. Bounds: `unknown` share reported, and every rate given as a two-sided bound (unknown counted as human, unknown counted as AI). A report whose bounds are wider than its confidence interval is reporting a data-quality problem, not a precision problem, and must say so.
8. Witnesses (L3): `station-only / active_time <= 0.5 %`, `disputed / active_time <= 2 %`, offset spread <= `tau`.

## 4. Residual risks that no check in this table closes

Three tactics survive all levels and must be handled by disclosure rather than measurement. First, choosing an easy deployment (environment, task mix, customer) is legitimate and invisible to the metric; the standard can only require task-type and environment descriptors. Second, an operator who acts through a control path the logger does not observe and that never crosses a monitored network (direct radio, local joystick) defeats L3 and the network witness; only physical audit or L4 attestation of the full input path addresses it. Third, batched or store-and-forward human planning (a person writes the plan the robot then executes "autonomously") is detectable only if plan-ingestion events are in the schema and counted as human time; the standard should make `plan_received` with a human author a `human_remote` event of declared duration.
